### 2.3 术语对照与统一

| 概念 | 协议架构用词 | 交互设计用词 | 经济模型用词 | 视频分镜用词 | **统一建议** |
|------|-------------|-------------|-------------|-------------|-------------|
| 创建衍生作品 | `derive`, `derivation` | 引用、衍生、Remix | 引用、二次创作 | 引用、衍生 | **衍生** (Derivation) |
| 父子关系 | `parents[]`, `children[]` | 引用链、衍生树 | 上游、下游 | 创作血缘 | **引用链** (Reference Chain) |
| 原创者 | `original` | - | 原创者、上游末端 | 原创者 | **原创者** (Original Creator) |
| 直接创作者 | `directCreator` | - | 层级 0 | 直接创作者 | **创作者** (Creator) |
| 分润池 | `upstreamPool` | 收益分配 | 上游分润池 | 上游池 | **分润池** (Royalty Pool) |
| 使用权 | `usagePrice` | 购买使用权 | 使用权 | 作品被使用 | **使用权** (Usage Rights) |
| 衍生权 | `derivativePrice` | 可衍生 | - | - | **衍生权** (Derivative Rights) |

⚠️ **注意事项**:
- 协议架构使用 `derive/derivation` 作为技术术语，但 UI 层面使用"引用"更直观
- 建议在技术文档中保留 `derive`，在产品界面使用"引用"或"衍生"
- 经济模型中的"上游"与协议中的"parents"对应，需在文档中明确映射

### 依赖关系说明

```
核心依赖链:
────────────

               │
               └── EchoRights (读取引用关系)

并行开发可行性:
────────────────
✅ 合约开发 与 UI 组件开发 可并行 (使用 Mock 数据)
✅ 经济模型计算器 与 合约开发 可并行
✅ 视频脚本 与 技术实现 可并行

❌ 视频录屏 依赖 前端页面完成
❌ 合约部署 依赖 合约开发完成
❌ 前端集成 依赖 合约部署地址
```

### 潜在阻塞点

| 阻塞点 | 风险等级 | 影响 | 缓解方案 |
|--------|----------|------|----------|
| 合约 Gas 费用过高 | 🔴 高 | 用户铸造成本高 | 提前使用优化技巧，准备优化方案 |
| 分润算法边界条件 | 🔴 高 | 长引用链分润异常 | 设计阶段充分测试长链场景 |
| 音频存储成本 | 🟡 中 | IPFS 费用不可控 | 使用 Arweave 永久存储 |
| 钱包连接兼容性 | 🟡 中 | 部分浏览器不支持 | 测试主流钱包，准备降级方案 |
| 视频渲染时间 | 🟢 低 | 后期制作延期 | 提前开始录屏，使用代理素材 |
