## 一、链上基础设施 Layer 1

### 1.1 核心智能合约组

| 合约 | 职责 | 技术要点 |
|------|------|----------|
| **ShiShuRegistry** | 势枢注册表 | 存储三维坐标、势场边界、预言机接口 |
| **ShiPositionRegistry** | 势位注册表 | 六爻坐标、势能计算、跃迁历史 |
| **ShiFieldRegistry** | 势场注册表 | 64区域、周期Merkle根、资产-区域映射 |
| **ShiMerkle** | Merkle验证器 | 资产归属验证、证明校验 |
| **EchoCore** | 主协议合约 | 资产登记（非铸造）、四权配置存储 |
| **RevenueSplitter** | 收益分配器 | 自动分润、级联清算 |
| **PolicyEngine** | 策略引擎 | 有效配置计算、冲突检测 |

### 1.2 四权配置合约

```
用权 (Usage) —— 谁能使用、付多少钱
衍权 (Derivative) —— 谁能衍生、如何分成
扩权 (Expansion) —— 谁能发现、传播范围
益权 (Benefit) —— 收益分配、份额交易
```

### 1.3 共识与验证合约

- **PoU验证合约**：验证使用证明的真实性
- **验证者注册表**：验证者质押、权重计算
- **挑战期合约**：7天争议窗口、罚没机制
- **仲裁合约**：争议裁决、异常处理

### 1.4 经济合约

- **ECHO代币合约**：DCEP 1:1映射、托管账户
- **收益权拆分合约**：益权分层、份额交易
- **质押合约**：验证者质押、解锁机制

## 二、链下执行基础设施 Layer 2

### 2.1 沙箱执行网络

| 组件 | 职责 | 类型 |
|------|------|------|
| **入口沙箱** | 验证用户余额、预扣费用、权限检查 | ECHO控制 |
| **创作者沙箱** | 执行Skill逻辑、私有模型、生成ZKP | 创作者主权 |
| **结算沙箱** | 验证ZKP、实际扣费、收益分配、更新链上状态 | ECHO控制 |

**强制混合模式**：
```
ECHO入口 → 创作者沙箱（私域） → ECHO结算
     ↓              ↓                ↓
验证余额    执行+生成ZKP证明    验证证明+分配
```

### 2.2 沙箱技术栈

- **容器化**：Docker / gVisor / Kata Containers
- **隔离级别**：
  - L1: WASM（轻量、快速）
  - L2: gVisor（系统调用过滤）
  - L3: Kata（硬件级隔离）
- **资源计量**：CPU时间、内存使用、网络IO
- **ZKP生成**：Risc0 / SP1 / zk-SNARK

### 2.3 计算资源层

- **边缘节点**：就近执行、降低延迟
- **GPU集群**：AI模型推理
- **异步结算队列**：高并发处理

## 三、数据基础设施 Layer 3

### 3.1 事件流系统（真相来源）

```
Kafka事件流（热数据）
    ↓
PostgreSQL（温数据，持久化）
    ↓
IPFS（冷数据，归档）
```

**核心事件类型**：

| 事件 | 触发场景 | 维度 |
|------|----------|------|
| `AssetCreated` | 创作者登记资产 | — |
| `UsageOccurred` | 用户调用Skill | 时间维度 |
| `DeploymentEvent` | Skill部署到新沙箱 | 空间维度 |
| `DerivativeCreated` | 基于资产创建衍生 | 关系维度 |
| `CitationEvent` | 资产被引用 | 关系维度 |
| `ShiStateChanged` | 势位跃迁 | — |
| `PolicyAdjusted` | 配置调整 | — |
| `RevenueDistributed` | 收益分配 | — |

### 3.2 状态存储

| 存储 | 用途 | 特点 |
|------|------|------|
| **Redis** | 当前状态缓存 | 热数据、O(1)查询、可重建 |
| **PostgreSQL** | 蓝图规则、事件缓冲 | 事务支持、复杂查询 |
| **IPFS** | 资产内容、详细日志 | 去中心化、内容寻址 |
| **链上** | 权属蓝图哈希、收益记录 | 不可篡改、成本高 |

### 3.3 ShiGraph计算引擎

```
每小时执行：
1. 读取事件流（过去90天）
2. 计算三维坐标 [时间, 空间, 关系]
3. 映射到64卦 / 技术命名（Stage.SEED/MATURE）
4. 检测变势 → 触发约束引擎
5. 更新Redis缓存
```

**输入**：事件流（Usage/Deployment/Derivative/Citation）
**输出**：三维坐标 + 六爻坐标 + 势能度量

### 3.4 势场测绘系统（每周）

```
Step 1: 数据采集 → 全网资产4维配置
Step 2: t-SNE降维 → 2D平面
Step 3: DBSCAN聚类 → 区域标签
Step 4: 特征描述 + 卦名匹配
Step 5: 计算Merkle Root + ZK proof
Step 6: 链上提交 → ShiFieldRegistry.createEpoch()
```

## 四、验证与共识基础设施

### 4.1 PoU（使用证明）系统

```
用户使用Skill
    ↓
沙箱执行并计量
    ↓
生成PoU证明（含时间戳、使用量、哈希、ZKP）
    ↓
提交验证节点
    ↓
验证者验证（沙箱签名、数据合理性）
    ↓
7天挑战期
    ↓
无争议 → 确认上链 → 更新ShiGraph
有争议 → 仲裁处理
```

### 4.2 验证者网络

**权重公式**：
```
Weight = 50% × 使用时长 + 30% × 质押金额 + 10% × 验证准确率 + 10% × 活跃度
```

**验证者工具**：
- 验证节点客户端
- 质押管理界面
- 验证历史查询
- 收益追踪

### 4.3 异常检测

| 检测类型 | 方法 | 阈值 |
|----------|------|------|
| 时间爆发 | Z-Score | >3 |
| 空间跳跃 | Z-Score | >3 |
| 关系集群 | Z-Score | >3 |
| 新势场现象 | Z-Score | >4 |

## 十、安全与隐私基础设施

### 10.1 密码学方案

| 技术 | 用途 | 优先级 |
|------|------|--------|
| **零知识证明** | 验证使用发生而不泄露内容 | MVP后 |

| **沙箱隔离** | 执行环境隔离 | MVP |
| **Merkle证明** | 资产归属验证 | MVP |

### 10.2 隐私保护原则

```
❌ 不允许ECHO掌握资产数据明文
❌ 不允许ECHO进入创作者沙箱
✅ ECHO只验证边界（PoU证明）
✅ 创作者拥有完全主权
```

### 10.3 审计与合规

- 使用记录审计（链上哈希）
- 收益分配审计（透明可追溯）
- 数据合规（跨境、GDPR）

## 十一、经济基础设施

### 11.1 货币系统

```
用户：DCEP充值 → ECHO（1:1映射）
创作者：ECHO → DCEP提现
流通：ECHO仅在系统内部
```

**托管方案**：
- 银行合作（合规）
- 第三方支付（启动快）
- 混合模式（灵活）

### 11.2 收益分配模型

```
用户使用Skill支付1 ECHO：
├── 创作者: 0.99 (99%)
├── 验证者: 0.009 (0.9%，按权重)
└── ECHO协议: 0.001 (0.1%)
```

**衍生分配**：
```
Skill B（衍生）使用Skill A：
B被使用时 → 10%给A（原创者）
```

### 11.3 收益权市场

- 收益权拆分（创作者出售未来收益30%）
- 投资者视角（现金流型/增长型/影响力型）
- 分层解锁（冷启动→成熟期）
