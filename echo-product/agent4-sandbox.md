### 1.1 轻量级沙箱 | WebAssembly Sandbox

| 维度 | 详情 |
|------|------|
| **功能名称** | WebAssembly 轻量级沙箱 |
| **安全威胁** | 1. 恶意代码执行导致计算资源耗尽<br>2. 内存越界访问<br>3. 侧信道攻击（时序分析）<br>4. 二次编译时植入恶意逻辑 |
| **防护方案** | 1. **能力模型(Capability)**: 显式声明所需能力，拒绝隐式权限<br>2. **线性内存隔离**: 单一线性内存空间 + 边界检查<br>3. **确定性执行**: 无未定义行为，执行路径可预测<br>4. **模块签名验证**: 执行前验证 WASM 模块哈希与签名 |
| **性能影响** | 启动时间: <10ms<br>内存开销: ~MB 级<br>执行速度: 接近原生 (~80-95%) |
| **适用场景** | 1. ECHO 音乐资产元数据解析<br>2. 图像资产缩略图生成<br>3. 资产格式校验与转换<br>4. 简单数学/逻辑运算 |

**技术细节:**
```yaml
wasm_sandbox:
  runtime: wasmtime  # 或 wasmer
  config:
    max_memory: 128MB
    max_execution_time: 5s
    fuel_consumption: true  # 指令计数限制
    capabilities:
      - stdio
      - clock
      # 无网络能力
      # 无文件系统能力
  security:
    module_verification: true
    signature_required: true
    allow_untrusted: false
```

### 1.2 中量级沙箱 | gVisor 系统调用沙箱

| 维度 | 详情 |
|------|------|
| **功能名称** | gVisor 系统调用拦截沙箱 |
| **安全威胁** | 1. 内核漏洞利用逃逸<br>2. 容器逃逸攻击<br>3. 恶意网络请求（C2 通信）<br>4. 文件系统遍历/敏感文件读取<br>5. 资源耗尽攻击（fork bomb） |
| **防护方案** | 1. **用户态内核(Sentry)**: 拦截所有系统调用，在 Go 运行时模拟内核行为<br>2. **9P 文件系统代理**: 受限文件访问，白名单目录<br>3. **网络栈隔离**: 独立的 TCP/IP 栈，出站流量经代理审计<br>4. **Seccomp-BPF**: 额外系统调用过滤层<br>5. **命名空间隔离**: PID/UTS/IPC/Mount/Network Namespace |
| **性能影响** | 启动时间: ~100-300ms<br>内存开销: ~50-100MB<br>系统调用开销: 2-3x（I/O 密集型影响较大） |
| **适用场景** | 1. 第三方技能执行<br>2. 需要网络访问的资产处理（如 NFT 元数据获取）<br>3. Python/Node.js 脚本执行<br>4. API 集成类任务 |

**技术细节:**
```yaml
gvisor_sandbox:
  runtime: runsc
  config:
    platform: ptrace  # 或 kvm（更好性能）
    network: host     # 或 none/私有网络
    filesystem:
      rootfs: read-only
      allowed_paths:
        - /tmp: rw
        - /workspace: rw
      denied_paths:
        - /proc
        - /sys
        - /etc/passwd
    limits:
      cpu: 1.0
      memory: 512MB
      pids: 100
      file_descriptors: 1024
    network_policy:
      outbound:
        - allow: "*.echo.io"
        - allow: "*.ipfs.io"
        - deny: "*"
```

### 1.3 重量级沙箱 | Kata Containers / Firecracker

| 维度 | 详情 |
|------|------|
| **功能名称** | Kata/Firecracker 硬件虚拟化沙箱 |
| **安全威胁** | 1. 内核级漏洞利用<br>2. 硬件虚拟化逃逸<br>3. 侧信道攻击（Spectre/Meltdown）<br>4. 持久化后门植入<br>5. 供应链攻击（预置恶意代码） |
| **防护方案** | 1. **硬件虚拟化**: 独立内核 + 独立内核空间，与 Host 完全隔离<br>2. **不可变基础设施**: 只读根文件系统，临时写入层<br>3. **安全启动**: 测量启动（Measured Boot）验证镜像完整性<br>4. **vTPM 支持**: 远程证明（Remote Attestation）<br>5. **内存加密**: AMD SEV / Intel TDX（可选） |
| **性能影响** | 启动时间: ~500ms-2s（Firecracker 可优化到 <125ms）<br>内存开销: ~128-256MB（轻量内核）<br>执行速度: 接近原生（无系统调用拦截开销） |
| **适用场景** | 1. 需要编译执行的代码（C++/Rust 构建）<br>2. 复杂链上合约交互<br>3. 未知来源的第三方代码<br>4. 需要完整 Linux 环境的任务<br>5. 高价值资产处理 |

**技术细节:**
```yaml
kata_sandbox:
  runtime: kata-runtime
  hypervisor: qemu  # 或 cloud-hypervisor, firecracker
  config:
    machine_type: q35
    kernel: /opt/kata/vmlinuz-container
    image: /opt/kata/kata-containers.img
    security:
      rootfs_type: read-only
      confidential_computing: false  # 可选开启 SEV/TDX
    resources:
      default_vcpus: 2
      default_memory: 2048
      memory_slots: 10
      enable_mem_prealloc: false
    agent:
      container_pipe_size: 0
      dial_timeout: 45
```

### 2.1 ECHO 音乐资产安全播放

| 维度 | 详情 |
|------|------|
| **功能名称** | ECHO 音频资产安全播放引擎 |
| **安全威胁** | 1. 音频数据在内存中被导出<br>2. 播放过程被录音截获<br>3. 解码器漏洞导致代码执行<br>4. 音频指纹被恶意提取用于盗版追踪<br>5. 频谱/波形分析逆向 |
| **防护方案** | 1. **流式解密**: 边解密边播放，不保留完整明文<br>2. **安全音频路径**: 加密内存 → 硬件安全模块 → DAC（类似 DRM 路径）<br>3. **解码器隔离**: 在 WASM/gVisor 中运行，最小化攻击面<br>4. **播放水印**: 叠加用户 ID 指纹的不可听水印<br>5. **内存加密**: 敏感音频缓冲区使用 AES-256-GCM 加密<br>6. **防截屏/录音**: 操作系统级标记（如 macOS `kCGDisplayStreamProtect`） |
| **性能影响** | 解码延迟: +5-15ms<br>CPU 开销: +10-20%（加密/水印）<br>内存占用: 仅当前播放帧，不缓冲完整文件 |
| **适用场景** | 1. 高价值音乐 NFT 预览<br>2. 订阅制音乐播放<br>3. 创作者 demo 分享<br>4. 版权受限内容的 Agent 处理 |

**技术架构:**

### 2.2 ECHO 图像资产安全渲染

| 维度 | 详情 |
|------|------|
| **功能名称** | ECHO 图像资产安全渲染引擎 |
| **安全威胁** | 1. 原始像素数据被提取<br>2. 渲染过程被截屏捕获<br>3. 图像解码漏洞（如 libpng 漏洞）<br>4. 隐写数据被提取<br>5. 渲染结果水印被去除 |
| **防护方案** | 1. **GPU 隔离渲染**: 在独立 GPU 上下文渲染，禁止 CPU 读取回传<br>2. **离屏渲染**: Framebuffer Object (FBO) 渲染，不经过主屏幕缓冲区<br>3. **安全解码**: 自定义图像解码器（WASM），禁用高危特性<br>4. **视觉水印**: 屏幕叠加用户 ID/时间戳（类似 Twitter 截图水印）<br>5. **防截屏**: Android FLAG_SECURE / iOS screenCaptureDidChange 检测<br>6. **输出指纹**: 每个渲染结果微幅调整像素值，唯一标识 |
| **性能影响** | 渲染延迟: +20-50ms（GPU 同步）<br>显存占用: 2x（离屏缓冲区）<br>输出质量: 99.9%（水印几乎不可见） |
| **适用场景** | 1. 高分辨率艺术 NFT 预览<br>2. 数字藏品展示<br>3. 受限图像的 AI 训练数据预览<br>4. 创作者作品集安全展示 |

**技术架构:**

### 2.3 防提取与防复制技术

| 维度 | 详情 |
|------|------|
| **功能名称** | 资产防提取与防复制系统 |
| **安全威胁** | 1. 内存 dump 提取原始数据<br>2. 网络流量抓取<br>3. 屏幕录制/截屏<br>4. 调试器附加分析<br>5. 虚拟机快照回滚分析 |
| **防护方案** | 1. **内存加密**: 敏感数据始终加密，仅在 TEE 内解密<br>2. **防调试**: ptrace 检测，调试器附加自动退出<br>3. **防虚拟化**: 检测虚拟机环境，拒绝执行或降级功能<br>4. **运行时完整性**: 代码签名验证，内存完整性检查<br>5. **审计水印**: 每个输出实例带唯一标识，泄露可溯源<br>6. **阅后即焚**: 临时访问令牌，过期自动失效 |
| **性能影响** | 安全检查: +5-10ms<br>内存加密: +15-30% CPU<br>水印计算: +20-40ms |
| **适用场景** | 所有高价值 ECHO 资产的处理与展示场景 |

**防提取技术矩阵:**

| 攻击向量 | 防护技术 | 实现方式 |
|----------|----------|----------|
| 内存 Dump | 内存加密 | AES-256-GCM，仅 TEE 可解密 |
| 网络抓包 | TLS 1.3 + 证书固定 | mTLS 双向认证 |
| 屏幕录制 | FLAG_SECURE / 水印 | Android/iOS API + 视觉覆盖 |
| 调试器 | ptrace 陷阱 | SIGTRAP 自保护 |
| 虚拟机 | CPUID 检测 | 检测 VM 特征，拒绝或降级 |
| 快照回滚 | 时间令牌 | 区块链时间戳验证 |

### 3.1 第三方技能权限模型

| 维度 | 详情 |
|------|------|
| **功能名称** | 技能最小权限模型 (Skill Capability Model) |
| **安全威胁** | 1. 技能申请过多权限<br>2. 权限提升攻击<br>3. 权限绕过<br>4. 权限滥用（如读取无关用户数据） |
| **防护方案** | 1. **显式声明**: 技能必须声明所需权限，无隐式权限<br>2. **能力列表**: 文件读取、网络访问、资产访问、加密操作等细粒度能力<br>3. **用户授权**: 执行前向用户展示权限请求，需明确同意<br>4. **动态授权**: 敏感操作（如资产解密）需二次确认<br>5. **权限审计**: 所有权限使用记录上链，可追溯 |
| **性能影响** | 权限检查: <1ms / 调用<br>授权流程: 用户交互耗时 |
| **适用场景** | 所有第三方技能执行前检查 |

**权限等级:**

```yaml
skill_permissions:
  # Level 1: 基础计算
  compute:
    - math: 数学运算
    - string: 字符串处理
    - crypto: 加密/哈希（仅标准算法）
  
  # Level 2: 受限 I/O
  io_restricted:
    - fs_read: 读取指定路径
    - fs_write: 写入临时目录
    - env_read: 读取环境变量（白名单）
  
  # Level 3: 网络访问
  network:
    - http_get: HTTP GET 请求（域名白名单）
    - http_post: HTTP POST 请求（需额外审批）
  
  # Level 4: 资产访问
  asset:
    - asset_read: 读取资产元数据
    - asset_decrypt: 解密资产内容（需用户授权）
    - asset_transform: 转换资产格式
  
  # Level 5: 系统级
  system:
    - process_spawn: 启动子进程
    - kernel_module: 加载内核模块（禁止）
```

### 3.3 超时与熔断机制

| 维度 | 详情 |
|------|------|
| **功能名称** | 技能执行超时与熔断系统 |
| **安全威胁** | 1. 无限循环/死锁<br>2. 长时间占用资源<br>3. 慢速攻击<br>4. 级联故障扩散 |
| **防护方案** | 1. **执行超时**: 最大执行时间限制，超时强制终止<br>2. **空闲超时**: 无活动超过阈值即终止<br>3. **熔断器模式**: 连续失败/异常后拒绝执行<br>4. **优雅降级**: 熔断后返回缓存或默认结果<br>5. **指数退避**: 重试间隔逐步增加 |
| **性能影响** | 超时检查: 每 100ms 一次，开销可忽略 |
| **适用场景** | 所有技能执行实例 |

**熔断策略:**

```yaml
circuit_breaker:
  failure_threshold: 5      # 连续失败 5 次后熔断
  success_threshold: 3      # 连续成功 3 次后恢复
  timeout_duration: 30s     # 超时时间
  half_open_max_calls: 3    # 半开状态最大试探次数
  blacklist_duration: 1h    # 黑名单持续时间
  
  behaviors:
    - type: timeout
      action: kill          # 超时: 强制终止
    - type: memory_exceeded
      action: kill          # 内存超限: 强制终止
    - type: cpu_exceeded
      action: throttle      # CPU 超限: 限流
    - type: suspicious_network
      action: blacklist     # 可疑网络: 拉黑
```

### 4.3 恶意合约交互保护

| 维度 | 详情 |
|------|------|
| **功能名称** | 智能合约交互安全防护 |
| **安全威胁** | 1. 钓鱼合约（伪装成知名合约）<br>2. 无限授权（approve 攻击）<br>3. 重入攻击<br>4. 权限升级攻击<br>5. 代理合约恶意升级 |
| **防护方案** | 1. **合约白名单**: 仅允许与已知安全合约交互<br>2. **授权限制**: `approve` 必须指定具体金额，禁止无限授权<br>3. **静态分析**: Slither/Mythril 预检合约代码<br>4. **行为监控**: 异常模式检测（如突然的大量资金转移）<br>5. **代理合约审计**: 验证实现合约地址，监控升级事件 |
| **性能影响** | 静态分析: +1-5s（首次）<br>白名单检查: <10ms |
| **适用场景** | 所有合约交互调用 |

**合约风险等级:**

| 风险等级 | 特征 | 处理方式 |
|----------|------|----------|
| **🟢 安全** | 已审计合约、知名协议、长时间无异常 | 允许直接交互 |
| **🟡 警告** | 新合约、未审计、低流动性 | 额外确认，限额交互 |
| **🟠 危险** | 疑似钓鱼、异常行为、用户举报 | 禁止交互，告警 |
| **🔴 黑名单** | 已知恶意合约、已发生盗币 | 永久禁止，记录上报 |

### 5.1 多沙箱并行管理

| 维度 | 详情 |
|------|------|
| **功能名称** | 多沙箱并行执行与调度 |
| **安全威胁** | 1. 资源竞争导致拒绝服务<br>2. 沙箱间信息泄露<br>3. 调度器被操纵<br>4. 优先级反转攻击 |
| **防护方案** | 1. **资源配额**: 每个用户/任务分配独立资源池<br>2. **公平调度**: CFS（完全公平调度器）避免饥饿<br>3. **优先级队列**: 实时任务优先，批量任务错峰<br>4. **沙箱隔离**: 沙箱间禁止直接通信，必须通过编排器<br>5. **负载均衡**: 自动分布到不同物理节点 |
| **性能影响** | 调度开销: <5ms<br>上下文切换: 取决于沙箱类型 |
| **适用场景** | 高并发任务处理 |

**调度策略:**

```yaml
scheduling:
  policies:
    - name: "priority"
      weight: 50
      queues:
        - name: "critical"
          priority: 100
          max_wait: 0s
        - name: "normal"
          priority: 50
          max_wait: 30s
        - name: "batch"
          priority: 10
          max_wait: 5m
    
    - name: "fair_share"
      weight: 30
      min_share: 10%
      max_share: 50%
    
    - name: "gang"
      weight: 20
      # 多沙箱协作任务，同时调度
  
  constraints:
    - anti_affinity:  # 同一用户的任务分散
        key: "user_id"
        spread: "node"
    - resource_fit:
        cpu: "best_effort"
        memory: "exact"
```

### 5.2 沙箱间安全通信

| 维度 | 详情 |
|------|------|
| **功能名称** | 沙箱间受控通信机制 |
| **安全威胁** | 1. 沙箱间直接通信绕过安全审计<br>2. 消息注入攻击<br>3. 侧信道通信（时序/缓存）<br>4. 拒绝服务攻击（洪泛消息） |
| **防护方案** | 1. **中介通信**: 所有通信必须通过 Sidecar/编排器<br>2. **消息验证**: 消息签名验证，防止伪造<br>3. **流量控制**: 速率限制，防止洪泛<br>4. **内容审计**: 敏感操作消息记录审计日志<br>5. **最小通信**: 默认禁止通信，显式声明才允许 |
| **性能影响** | 消息延迟: +1-5ms（中介转发）<br>吞吐量: 受限于中介带宽 |
| **适用场景** | 需要协作的多沙箱任务 |

**通信模式:**

| 模式 | 机制 | 安全级别 | 适用场景 |
|------|------|----------|----------|
| **无通信** | 完全隔离 | ⭐⭐⭐⭐⭐ | 独立任务，默认 |
| **单向流** | 只读数据流 | ⭐⭐⭐⭐ | 数据消费（如资产 → 渲染） |
| **请求-响应** | gRPC 调用 | ⭐⭐⭐⭐ | 技能调用服务 |
| **发布-订阅** | 消息队列 | ⭐⭐⭐ | 事件通知 |
| **共享内存** | 受限共享页 | ⭐⭐ | 高性能数据交换（需严格审计） |

### 5.3 沙箱生命周期管理

| 维度 | 详情 |
|------|------|
| **功能名称** | 沙箱创建、复用与销毁 |
| **安全威胁** | 1. 沙箱残留数据被后续任务读取<br>2. 沙箱被植入持久化后门<br>3. 僵尸沙箱占用资源<br>4. 沙箱逃逸后持续存在 |
| **防护方案** | 1. **热启动复用**: 预创建沙箱池，减少启动延迟<br>2. **深度清理**: 销毁时内存清零，文件系统粉碎<br>3. **最大寿命**: 沙箱运行超限时强制重建<br>4. **不可变镜像**: 沙箱文件系统只读，禁止修改<br>5. **优雅终止**: SIGTERM → 超时 → SIGKILL 阶梯终止 |
| **性能影响** | 冷启动: WASM <10ms, gVisor 100-300ms, Kata 500ms-2s<br>热启动: 接近零延迟<br>销毁: <100ms |
| **适用场景** | 所有沙箱实例 |

## 七、总结

### 7.1 架构总览

ECHO 沙箱安全架构采用**分层防御**设计：

1. **轻量级沙箱 (WASM)**: 纯计算场景，极致性能
2. **中量级沙箱 (gVisor)**: 平衡安全与功能，第三方技能主力
3. **重量级沙箱 (Kata)**: 最高安全级别，处理敏感资产

### 7.2 核心安全原则

| 原则 | 实现 |
|------|------|
| **最小权限** | 能力模型 + 显式声明 |
| **深度防御** | 多层沙箱 + 多重校验 |
| **不可信执行** | 所有代码在沙箱中执行 |
| **可审计** | 所有操作记录上链 |
| **可恢复** | 熔断机制 + 优雅降级 |

### 7.3 性能与安全权衡

| 场景 | 推荐沙箱 | 启动延迟 | 安全级别 |
|------|----------|----------|----------|
| 资产元数据解析 | WASM | <10ms | ⭐⭐⭐ |
| 第三方技能执行 | gVisor | 100-300ms | ⭐⭐⭐⭐ |
| 高价值资产处理 | Kata | 500ms-2s | ⭐⭐⭐⭐⭐ |
| 链上交易签名 | HSM/TEE | 10-50ms | ⭐⭐⭐⭐⭐ |
