# ECHO 规则与经济模拟器 — 架构设计提案 v0.1

> 核心定位：验证 **6 档视图约束** 对生态演化产生的结构性差异
> 对比基准：有 ECHO 视图约束 vs 纯市场自由生长

---

## 一、核心实验设计

### 1.1 双轨并行对比

| 维度 | 轨道 A：ECHO 世界 | 轨道 B：纯市场世界 |
|------|------------------|------------------|
| **视图约束** | 6 档授权级别强制生效 | 无授权层级，纯价格/口碑驱动 |
| **准入规则** | 白名单/规则授权/共识门槛 | 有钱就能买 |
| **衍生关系** | 需遵守母资源视图档位 | 自由 fork，无归属链 |
| **收益分润** | 按 ECHO 协议自动分润 | 无强制分润，自愿协商 |
| **同一初始化** | 相同 Agent 池、相同初始资源、相同随机种子 | 同上 |

**关键假设**：两轨道的唯一差异是「视图约束是否存在」，其他全部控制变量。

### 1.2 6 档视图引擎

```
L0 — 不开放（创作者独占）
L1 — 仅自用（创作者自己用，不对外）
L2 — 白名单（指定用户可用）
L3 — 规则授权（满足条件即可：价格+状态门槛）
L4 — 共识授权（需社群共识/投票）
L5 — 纯公开（无限制）
```

**规则引擎行为**：
- L0/L1：无交易发生，仅创作者自用收益
- L2：白名单用户可交易，非白名单不可见
- L3：动态条件判断（余额、信誉、持有其他资源等）
- L4：引入投票延迟 + 共识成本
- L5：纯市场行为，但保留衍生归属链

### 1.3 衍生链追踪

ECHO 世界的核心数据结构：
```
Resource {
  id,
  creator,
  parentId?,          // 衍生来源
  viewLevel,          // 0-5
  creationRound,
  price,
  // ECHO 特有
  derivedCount,       // 被衍生次数
  revenueShared,      // 已分润给上游的金额
  licenseHistory[]    // 授权记录
}
```

纯市场世界：无 `parentId`、`derivedCount`、`revenueShared`，fork 即独立。

## 二、Agent 行为模型

### 2.1 角色分类

| 角色 | 占比 | 核心行为 | 视图敏感度 |
|------|------|---------|-----------|
| **创作者** | 20% | 创建资源、设定视图档位、定价 | 高（主动选择视图） |
| **使用者** | 50% | 购买、使用、评价、申请衍生 | 中（受视图约束） |
| **衍生者** | 20% | 基于现有资源创建衍生 | 高（需遵守母资源视图） |
| **投机者** | 10% | 囤积、套利、炒价格 | 低（只关心利润） |

### 2.2 决策函数（简化版）

**创作者创建资源时选择视图档位**：
```
viewLevel = argmax(
  expectedRevenue(viewLevel),
  networkEffect(viewLevel),
  controlPreference(creatorType)
)
```

- 保守型创作者 → 倾向 L0/L2（控制力强，收入少）
- 开放型创作者 → 倾向 L3/L5（网络效应大，收入多但分散）
- 实验型创作者 → 动态调整（根据反馈改视图档位）

**使用者购买决策**：
```
buy = (utility > price) && (accessGranted(viewLevel, myStatus))
```
- L3 规则授权失败 → 使用者可能选择：积累条件 / 换资源 / 放弃
- 纯市场世界 → 只判断 `utility > price`

### 2.3 衍生请求流程差异

**ECHO 世界**：
1. 衍生者发现母资源
2. 检查母资源 `viewLevel`
3. L0/L1 → 不可衍生（尝试也会被拒绝）
4. L2 → 申请白名单（等待/概率批准）
5. L3 → 满足条件自动授权
6. L4 → 发起共识投票（延迟 N 轮）
7. L5 → 直接衍生，但需记录归属链 + 自动分润

**纯市场世界**：
1. 发现资源
2. Fork → 独立发布
3. 无归属链、无分润、无授权记录

## 三、经济模型

### 3.1 基础交易

```
交易价格 = basePrice * (1 + creatorReputation * 0.1) * demandFactor
```

### 3.2 ECHO 特有：分润链

```
衍生资源收入 → 创作者(70%) + 平台(5%) + 母资源(15%) + 祖父资源(10%)
```

（可调参数，此处用示例值）

纯市场世界：创作者 100%，无追溯分润。

### 3.3 视图切换成本（ECHO 特有）

创作者可以降级/升级视图档位：
- L5 → L3：立即生效，已有许可继续有效（sunset 不追回）
- L3 → L5：立即生效
- L2 白名单变更：下轮生效

切换成本：0（ECHO 承诺）vs 市场声誉损失（纯市场也有）

## 四、输出指标与对比维度

### 4.1 核心指标

| 指标 | 含义 | 预期 ECHO 优势 |
|------|------|---------------|
| **繁荣度** | 资源总数 * 活跃度 | 初期慢，后期稳 |
| **多样性** | Shannon 熵（资源类别分布） | 约束促进专业化 |
| **创作者基尼系数** | 收入分布不平等度 | 分润链降低集中度 |
| **衍生深度** | 最长衍生链长度 | 归属链鼓励衍生 |
| **用户满意度** | 获得期望资源的概率 | L3/L4 可能降低 |
| **生态韧性** | 头部创作者退出后的恢复速度 | 归属链保护 |

### 4.2 关键对比问题

1. **视图约束是否抑制了创新？** → 对比两轨道资源总数、多样性
2. **分润链是否让更多中小创作者获益？** → 对比基尼系数、中位数收入
3. **L4 共识授权是否造成效率损失？** → 对比 L4 资源占比 vs 其衍生成功率
4. **投机者是否利用视图套利？** → 对比投机者收益占比、市场波动率
5. **生态是否更抗脆弱？** → 模拟头部创作者突然退出，看恢复曲线

## 五、技术实现方案

### 5.1 选项对比

| 方案 | 前端 | 后端 | 部署 | 复杂度 |
|------|------|------|------|--------|
| A. 纯前端 SPA（复刻参考） | React/Vue | 无 | GitHub Pages | 低 |
| B. 前端 + 本地 Node 引擎 | React | Node.js (本地) | 本地运行 | 中 |
| C. 前端 + 云端后端 | React | Cloudflare Workers / Vercel | 自动部署 | 中 |
| D. 全静态预计算 | 纯 HTML/JS | 无（预生成数据集） | GitHub Pages | 低 |

**推荐**：方案 A 起步（纯前端），与参考模拟器一致。后续如需持久化/多人协作再迁移到 C。

### 5.2 引擎架构（纯前端）

```
SimulationEngine {
  // 双轨道状态
  echoWorld: WorldState
  marketWorld: WorldState
  
  // 配置
  config: {
    rounds: 5000,
    agentCount: 200,
    initialResources: 50,
    seed: 12345,
    viewLevelDistribution: 'random' | 'uniform' | 'realistic'
  }
  
  // 运行
  step() // 单轮推进
  run()  // 全量运行
  compare() // 生成对比报告
}

WorldState {
  round: number
  agents: Agent[]
  resources: Resource[]
  transactions: Transaction[]
  metrics: MetricsSnapshot[]
}
```

### 5.3 UI 模块

1. **双仪表盘**（并排）：ECHO 世界 vs 市场世界，实时指标对比
2. **推演控制**：启动/暂停/单步/重置/倍速
3. **资源浏览器**：当前所有资源列表，可筛选视图档位
4. **衍生树可视化**：选中资源后展示其衍生子树（ECHO 世界特有）
5. **事件日志**：交易、衍生、视图切换、共识投票
6. **规则配置面板**：调整分润比例、视图档位分布、Agent 行为参数
