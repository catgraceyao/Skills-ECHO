## 三、会议上收到的关键反馈（需修改）

### 3.1 模块层级问题（Seaman 提出）
**反馈**：6 个模块不在同一个层级，需要重新梳理：

- **时间线三阶段**（核心主线）：
  - 模拟前 → 规则配置（Rule Configurator）
  - 模拟中 → 推演播放器（Simulation Player）
  - 模拟后 → 系统仪表盘（System Dashboard）
  - 这三个形成「前-中-后」清晰时间轴

- **观察维度**（辅助视角）：
  - 资源视角 → 资源浏览器 + 资源详情
  - 用户视角 → 用户浏览器 + 用户详情
  - 这两个是观察维度，不是时间阶段

**雅怡需要做的**：重新梳理信息架构，区分「时间主线」和「观察维度」两个层次。

### 3.2 推演播放器最需细化（多方确认）
**反馈**：推演播放器是前端最具特色的核心功能，但目前设计最粗糙。

**需要细化**：
- 动态回放的具体展示形式（网络图？时间轴？）
- 多视角切换：宏观全局 → 中观领域 → 微观个体
- 事件高亮系统：新资源诞生、大额交易、衍生链形成、市场异常、用户破产
- 多方案对比：左右分屏 / 三屏对比，同步时间轴控制
- 与后端的接口：每帧数据如何获取、播放/暂停/快进/跳转的控制逻辑

### 3.3 原型要更快、更具体地输出
**反馈**：王楠（前端）明确表示：
- 功能好做，但「具体长什么样」不确定
- 需要交互流程和原型，哪怕是单个页面或片段，随时发出来都可以
- 不需要等到周末才发完整版，周中随时发片段即可

## 四、雅怡需要立即交付的具体需求

### 4.1 第一优先级：推演播放器细化设计
**目标**：把最粗的模块做成最详细的原型

需产出：
- [ ] 推演播放器的页面结构（线框图级别）
- [ ] 三种视角的切换逻辑和展示形式
- [ ] 时间轴控制条的交互细节（播放/暂停/快进/跳转/流速）
- [ ] 事件高亮的视觉设计和触发条件
- [ ] 多方案对比的排版（2方案 / 3方案）
- [ ] 与后端的数据接口需求（每帧需要什么数据）

### 4.2 第二优先级：模块层级重梳理
**目标**：重新组织信息架构，让6个模块有清晰的层次关系

需产出：
- [ ] 新的信息架构图（区分时间主线和观察维度）
- [ ] 模块间跳转关系的更新
- [ ] 导航结构的调整（顶部导航 + 左侧快捷栏）

### 4.3 第三优先级：与前端对接的细化
**目标**：让王楠、曼姐能开始写代码

需产出：
- [ ] 每个模块的低保真原型（至少关键页面）
- [ ] 核心交互流程的标注（如：筛选后列表如何刷新、点击卡片如何下钻）
- [ ] 与后端接口的对齐（Swagger / OpenAPI 格式）
- [ ] 东方美学配色的具体 CSS 色值（已有）

### 4.4 第四优先级：演示模式设计（决策者场景）
**目标**：支持决策者汇报与演示

需产出：
- [ ] 自动播放模式（按预设脚本播放，无需手动控制）
- [ ] 关键帧自动停留 + 解说文字
- [ ] 全屏模式（隐藏控制按钮，只展示可视化）
- [ ] 导出视频/GIF（未来版本）

## 六、关键接口（需要雅怡与听风对齐）

| 接口 | 用途 | 优先级 |
|------|------|--------|
| GET /api/simulation/status | 仪表盘实时刷新 | 高 |
| GET /api/resources | 资源浏览器 | 高 |
| GET /api/resources/:id | 资源详情 | 高 |
| GET /api/agents | 用户浏览器 | 中 |
| GET /api/agents/:id | 用户详情 | 中 |
| POST /api/simulation/start | 启动模拟 | 高 |
| GET /api/simulation/snapshots | 推演播放器帧数据 | 最高 |
| POST /api/rules/config | 保存规则方案 | 高 |
| WebSocket /ws/events | 实时推送 | 高 |

## 七、美学规范（已确定，需落地）

- **宋代美学基底**：宣纸白 #F5F0E6 为底色，天水碧 #5AA4AE 为主色
- **配色比例**：主色 60% + 辅助色 25% + 点缀色 10% + 强调色 5%
- **语义色**：生产（天水碧）、消费（胭脂红）、衍生（缃色）、扩展（竹影青）
- **深色模式**：墨灰 #3A3A3A 底色，形成「水墨夜」意境
