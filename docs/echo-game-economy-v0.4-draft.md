## 第二章：安全参数（v0.1 初版）

> 📌 本章为 v0.4 新增。详细参数定义见 `security-params-v0.1.md`。本节只放摘要和上下文。

### 2.1 概述

ECHO 游戏经济模型面临三类主要攻击：

1. **大鲸鱼攻击**：大额资金操纵市场或连续获胜
2. **刷分攻击**：同一用户多账户刷高势位
3. **抢先跑（Front-running）**：利用区块时间差提前获取信息套利

安全参数层通过**链上约束 + 链下验证 + 博弈机制**三层防护，确保经济系统稳定。

### 2.2 大鲸鱼攻击防护

**核心参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| MAX_BET | 10 MEER | 单局投注上限（已在经济参数） |
| WIN_STREAK_DECAY | 阶梯式 | 连续获胜收益衰减 |
| LOCKUP_PERIOD | 90 天 | 锁仓线性释放 |
| EARLY_EXIT_PENALTY | 50% | 提前退出仅退 50% |

**收益衰减曲线**：

| 连续获胜局数 | 收益比例 | 说明 |
|-------------|---------|------|
| 第 1 局 | 100%（2.5%） | 基准收益 |
| 第 2 局 | 80%（2.0%） | 衰减 20% |
| 第 3 局起 | 60%（1.5%） | 衰减 40%，封顶 |
| 中断重置 | 100% | 任意失败或 5 局无参与 → 重置 |

**实现方式**：
- 链下：PotentialOracle 维护累加器（累计投入/累计收益），每局推送衰减系数
- 链上：合约接受签名后的系数，签名失效回退到默认 2.5%
- 复杂度：O(1) 查表，gas 可控

### 2.3 刷分攻击防护

**核心参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| MARK_THRESHOLD | 3 | 连续 3 次标记进入仲裁池 |
| MARK_DECAY_STEPS | [10000, 7000, 4000] | 标记后势位保留比例（basis points） |
| COOLDOWN_HOURS | 24 | 24h 无新标记清零计数 |
| RESET_WINDOW | 5 | 5 局无参与 → 计数器归零 |

**标记触发机制**：

| 检测维度 | 链下 | 链上 |
|----------|------|------|
| 同设备/IP | 前端指纹 + Node.js 中间层 | ❌ 无法读取 |
| 同一地址簇 | ❌ | 资金来源关联分析 |
| 时间模式 | ❌ | 固定间隔投注检测 |
| 社交图谱 | 邀请码验证 | ❌ |

**标记后处理**：

| 标记次数 | 势位保留 | 前端显示 | 状态 |
|----------|----------|----------|------|
| 1 | 100% | ⚠️ 警告 (1/3) | 不进仲裁 |
| 2 | 70% | ⚠️ 警告 (2/3) | 不进仲裁 |
| 3 | 40% | 🚨 进入仲裁池 | 触发 ArbiterRole |

**冷却机制**：
- 每次标记后启动 24h 观察期
- 24h 内无新标记 → 计数器清零（emit CooldownReset）
- 连续 5 局无参与 → 同样清零

### 2.4 抢先跑（Front-running）防护

**核心参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| BLOCK_TIME | 15-30s | Qitmeer 出块时间 |
| COMMIT_REVEAL | 3 区块 | 提交后 3 区块内不可撤回 |
| REVEAL_WINDOW | 3 区块 | 揭示窗口，超时作废 |

**commit-reveal 机制**：

1. **Commit 阶段**：用户提交 `keccak256(choice + nonce)`，不暴露明文
2. **确认阶段**：3 区块确认期，不可撤回
3. **Reveal 阶段**：提交明文 `choice + nonce`，合约验证 hash 匹配
4. **超时**：未在揭示窗口 reveal → 投注作废

**实现状态**：
- BattleGame 合约已实现两阶段提交（testnet 调试用明文，mainnet 强制 hash）
- 公示期锚定区块高度（非链下时间），防信息优势

## 第三章：算场架构设计（Phase 2 新增）

> 2026-06-05 会议共识：Shi-Graph 是 Phase 2 根基，四权六档是 Shi-Graph 的呼吸维度。

### 3.1 三层架构

```
输入层（事件流） → 场层（关系网络） → 输出层（可视化 + 结算）
```

#### 输入层（事件流）

| 事件类型 | 权重 | 说明 |
|----------|------|------|
| 铸造 | 1.0 | 基础值，防刷铸造套利 |
| 对战 | 2.0 | 核心经济活动，防攻击机制兜底 |
| 交易 | 1.5 | 流动性关键，高于铸造 |
| 持有 | 0.1/天 | 时间累积，奖励长期持有但防囤卡 |
| 社交（点赞/评论） | 0.3 | 社交信号，低但非零 |

**时间衰减**：指数衰减 `weight = e^(-λt)`，λ 由四权配置决定（通变参数控制衰减速率）。

**安全参数兜底**：
- 对战权重 2.0 不会导致刷对战套利：收益衰减（2.5%→2.0%→1.5%）+ 配对博弈（高势位强制互匹）+ 单局上限 10 MEER
- 交易权重 1.5（不是 0.5）：0.5 太低会导致流动性枯竭，1.5 保证二级市场活跃

#### 场层（关系网络）

- **节点**：每张卡 = 一个 ERC721 节点
- **边**：事件流连接节点，形成动态图
- **势位**：节点在关系网络中的拓扑位置（链下计算，链上只存事件）
- **图算法**：PageRank-like 变体 + 时间衰减 + 四权权重

#### 输出层（可视化 + 结算）

| 输出 | 来源 | 说明 |
|------|------|------|
| 势位值 → 视觉档位 | 云子非线性映射（6档） | 2D 折纸风格，低档位密集（新玩家易感知进步），高档位稀疏（高阶稀缺性） |
| 势位值 → 分账权重 | 益权配置决定 | 7方分账比例 |
| 势位值 → 访问权限 | 用权配置决定 | 谁可访问卡牌 |

### 3.2 四权六档与 Shi-Graph 绑定

四权是 Shi-Graph 的维度展开：
- **用权**：节点访问控制维度
- **衍权**：节点可衍生性维度
- **扩权**：节点传播范围维度
- **益权**：节点收益分配维度

六档光谱（0-5）：
- 0 档 = 完全封闭
- 5 档 = 完全开放
- 中间档 = 过渡态，由元规则约束

**元规则**：
- 用权开放 ≠ 衍权自动开放（需独立配置）
- 益权高 ≠ 扩权自动高（防高收益+无传播套利）
- 扩权开放 = 衍权必须 ≥ 一定档（传播需可衍生性）

### 3.3 事件权重默认值（已拍板）

| 事件 | 权重 | 理由 | 防攻击机制 |
|------|------|------|------------|
| 铸造 | 1.0 | 基础值，防刷铸造 | 首卡减免 DERIVE_DISCOUNT_BPS=5000 |
| 对战 | 2.0 | 核心经济活动 | 收益衰减 + 配对博弈 + 单局上限 10 MEER |
| 交易 | 1.5 | 流动性关键 | 无额外机制，权重本身激励流转 |
| 持有 | 0.1/天 | 时间累积 | 30/60/90 天势位衰减（非燃烧） |
| 社交 | 0.3 | 社交信号 | 低权重防刷社交套利 |

**权重设计原则**：
1. 激励多样性：不能只奖励对战（否则只有战士）
2. 防单一行为套利：任何单一行为权重不超过 2.0
3. 持有权重随时间递减：避免纯囤卡

## 第四章：经济摩擦成本分析（Phase 1 → Phase 2 → Phase 3）

### 4.1 Phase 1：ERC-721 务实妥协

**别扭**：把使用权写在 ERC-721 所有权框架里。

**摩擦成本**：

| 成本类型 | 说明 | 估算 |
|----------|------|------|
| Gas 成本 | 每次使用需 2 笔交易（approve + transfer） | 比原生标准多 ~1 笔 approve |
| UX 摩擦 | 用户需理解「先授权，再使用」两步逻辑 | 学习成本 |
| 经济摩擦 | 使用权定价困难（ERC-721 基于所有权稀缺性） | 需额外市场（时间/次数/期限） |

**覆盖方式**：摩擦成本被收益分配覆盖（7方分账中 10% 创作者收益），用户接受两步交易因为收益足够。

### 4.2 Phase 2：自定义 L2 / Qitmeer

**改进**：
- Gas 成本降低（自定义 L2 或 Qitmeer 原生支持使用权）
- UX 改善（一步完成使用）
- 经济摩擦降低（原生使用权标准，定价更自然）

**待实测**：Qitmeer Gas 结构 vs 以太坊差异大，需 testnet 实测验证 Gas 成本。

### 4.3 Phase 3：使用权原生标准

**目标**：1 笔交易完成使用权转移，无额外摩擦。

**经济模型兼容性**：
- 短期（Phase 1）：兼容但次优，摩擦被收益覆盖
- 中期（Phase 2）：摩擦降低，用户体验改善
- 长期（Phase 3）：无摩擦，经济模型完全兼容
