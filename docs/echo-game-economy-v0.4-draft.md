## 第二章：安全参数（v0.1 初版）

> 📌 本章为 v0.4 新增。详细参数定义见 `security-params-v0.1.md`。本节只放摘要和上下文。

### 2.1 概述

ECHO 游戏经济模型面临三类主要攻击：

1. **大鲸鱼攻击**：大额资金操纵市场或连续获胜
2. **刷分攻击**：同一用户多账户刷高势位
3. **抢先跑（Front-running）**：利用区块时间差提前获取信息套利

安全参数层通过**链上约束 + 链下验证 + 博弈机制**三层防护，确保经济系统稳定。

### 2.2 大鲸鱼攻击防护

**核心参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| MAX_BET | 10 MEER | 单局投注上限（已在经济参数） |
| WIN_STREAK_DECAY | 阶梯式 | 连续获胜收益衰减 |
| LOCKUP_PERIOD | 90 天 | 锁仓线性释放 |
| EARLY_EXIT_PENALTY | 50% | 提前退出仅退 50% |

**收益衰减曲线**：

| 连续获胜局数 | 收益比例 | 说明 |
|-------------|---------|------|
| 第 1 局 | 100%（2.5%） | 基准收益 |
| 第 2 局 | 80%（2.0%） | 衰减 20% |
| 第 3 局起 | 60%（1.5%） | 衰减 40%，封顶 |
| 中断重置 | 100% | 任意失败或 5 局无参与 → 重置 |

**实现方式**：
- 链下：PotentialOracle 维护累加器（累计投入/累计收益），每局推送衰减系数
- 链上：合约接受签名后的系数，签名失效回退到默认 2.5%
- 复杂度：O(1) 查表，gas 可控

### 2.3 刷分攻击防护

**核心参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| MARK_THRESHOLD | 3 | 连续 3 次标记进入仲裁池 |
| MARK_DECAY_STEPS | [10000, 7000, 4000] | 标记后势位保留比例（basis points） |
| COOLDOWN_HOURS | 24 | 24h 无新标记清零计数 |
| RESET_WINDOW | 5 | 5 局无参与 → 计数器归零 |

**标记触发机制**：

| 检测维度 | 链下 | 链上 |
|----------|------|------|
| 同设备/IP | 前端指纹 + Node.js 中间层 | ❌ 无法读取 |
| 同一地址簇 | ❌ | 资金来源关联分析 |
| 时间模式 | ❌ | 固定间隔投注检测 |
| 社交图谱 | 邀请码验证 | ❌ |

**标记后处理**：

| 标记次数 | 势位保留 | 前端显示 | 状态 |
|----------|----------|----------|------|
| 1 | 100% | ⚠️ 警告 (1/3) | 不进仲裁 |
| 2 | 70% | ⚠️ 警告 (2/3) | 不进仲裁 |
| 3 | 40% | 🚨 进入仲裁池 | 触发 ArbiterRole |

**冷却机制**：
- 每次标记后启动 24h 观察期
- 24h 内无新标记 → 计数器清零（emit CooldownReset）
- 连续 5 局无参与 → 同样清零

### 2.4 抢先跑（Front-running）防护

**核心参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| BLOCK_TIME | 15-30s | Qitmeer 出块时间 |
| COMMIT_REVEAL | 3 区块 | 提交后 3 区块内不可撤回 |
| REVEAL_WINDOW | 3 区块 | 揭示窗口，超时作废 |

**commit-reveal 机制**：

1. **Commit 阶段**：用户提交 `keccak256(choice + nonce)`，不暴露明文
2. **确认阶段**：3 区块确认期，不可撤回
3. **Reveal 阶段**：提交明文 `choice + nonce`，合约验证 hash 匹配
4. **超时**：未在揭示窗口 reveal → 投注作废

**实现状态**：
- BattleGame 合约已实现两阶段提交（testnet 调试用明文，mainnet 强制 hash）
- 公示期锚定区块高度（非链下时间），防信息优势

## 第三章：事件定义（链上）

> 详细字段和触发条件见 `security-params-v0.1.md`。本节只列事件名和触发时机摘要。

### 3.1 事件列表

| 事件名 | 触发条件 | 实时性 | 阶段 |
|--------|----------|--------|------|
| ScoreMarked | 检测到异常立即 emit | 实时 | 已有 |
| PotentialAttenuated | 用户交互时自动检查并 emit | 准实时 | Phase 2 新增 |
| ArbitrationTriggered | N=3 自动触发 / 手动举报 | 实时 | Phase 2 新增 |
| CooldownReset | 外部调用 checkCooldown() | 被动 | Phase 2 新增 |
| SybilCheckResult | 链下图谱验证后 emit | 准实时 | Phase 2 新增 |
| CommitSubmitted | 用户提交 commit hash | 实时 | 已有 |
| RevealSubmitted | 用户提交 reveal 明文 | 实时 | 已有 |

### 3.2 前端订阅建议

| 事件 | 前端展示 | 订阅方式 |
|------|----------|----------|
| ScoreMarked | 警告 badge / 仲裁池状态 | WebSocket / HTTP polling |
| PotentialAttenuated | 衰减后收益显示 | 用户交互时拉取 |
| ArbitrationTriggered | 仲裁池列表 | WebSocket |
| CooldownReset | 冷却倒计时清零 | 用户访问时调用 |
| SybilCheckResult | 验证状态徽章 | 准实时推送 |
| CommitSubmitted | "等待 reveal" 状态 | WebSocket |
| RevealSubmitted | "已 reveal" 状态 | WebSocket |
